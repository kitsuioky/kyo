Kyo can render the resolved theme colors into external app config files whenever the palette changes. This lets terminals, editors, browsers, launchers, and other apps follow the same colors as the shell.

Templates always render the variant selected by [`[theme].mode`](/kyo/theming/#mode), never
[`shell_mode`](/kyo/theming/#shell_mode), so pinning Kyo to dark keeps your apps on whatever `mode` resolves to.

To rerender enabled templates for the current palette without changing the theme, use
[Media & UI → Theme](/kyo/ipc/media-and-ui/#theme).

## Built-in Templates

Built-in templates ship with Kyo. Enable the built-in catalog, then opt in to the template IDs you want:

```toml
[theme.templates]
enable_builtin_templates = true
builtin_ids              = []        # opt-in; run: kyo theme --list-templates
```

`builtin_ids` selects which shipped templates run. An empty array means no built-in templates are applied.

Disabling a built-in template removes its generated Kyo theme file and undoes any Kyo-owned include or theme
selection that the template added to the application's config. Disabling `enable_builtin_templates` performs the same
cleanup for every selected built-in template.

Application configs must be writable for Kyo to remove those integrations. For declaratively managed configs such
as Home Manager symlinks into the Nix store, remove the Kyo include or theme selection from the declarative source.

List available built-in and configured template IDs:

```sh
kyo theme --list-templates
```

## Community Templates

Community templates are fetched from `https://api.kyo.dev/templates` and cached locally:

```toml
[theme.templates]
enable_community_templates = true
community_ids              = []        # opt-in; fetched from api.kyo.dev/templates
```

`community_ids` selects which community templates run. In **Settings → Templates**, enable community templates and use **Browse Templates** to search and filter the catalog (by category or enabled-only). Metadata and files are stored in `~/.local/state/kyo/community-templates/` (honoring `KYO_STATE_HOME`, then `XDG_STATE_HOME`).

Cached community template files are treated as editable local copies. Sync updates files only while their content still matches the last Kyo-written md5; local edits are preserved until you delete the edited cached file.

Community template discovery and updates require network access unless the selected template is already cached. [`shell.offline_mode`](/kyo/configuration/shell/#shell-settings) prevents outgoing HTTP requests, including community template requests.

## User Templates

User templates are declared directly in Kyo config:

```toml
[theme.templates.user.my_app]
input_path  = "$XDG_CONFIG_HOME/kyo/templates/my-app.css"
output_path = "$XDG_CONFIG_HOME/my-app/theme.css"
post_hook   = "my-app --reload-theme"
```

Defining `[theme.templates.user.<id>]` enables that user template. Set `enabled = false` on an entry to keep it available but inactive.

Relative paths resolve from the Kyo config directory. A leading `$XDG_CONFIG_HOME`, `$XDG_DATA_HOME`, `$XDG_STATE_HOME`, or `$XDG_CACHE_HOME` token is expanded using the XDG base directory defaults when the matching environment variable is not set.

User template entries support the same fields documented in [Template Entries](/kyo/theming/templates/#template-entries), including `input_path_modes`, `output_path_dynamic`, `colors_to_compare`, `compare_to`, `pre_hook`, `post_hook`, `post_action`, and `index`.

## Config Location

Put dotfile-managed templates in `~/.config/kyo/*.toml`:

```toml
# ~/.config/kyo/templates.toml
[theme.templates]
enable_builtin_templates   = true
enable_community_templates = true
builtin_ids                = []
community_ids              = []

[theme.templates.user.my_app]
input_path  = "$XDG_CONFIG_HOME/kyo/templates/my-app.css"
output_path = "$XDG_CONFIG_HOME/my-app/theme.css"
```

The same tables are valid in `settings.toml` because it is the final config overlay, but that file is managed by the GUI and runtime actions. Use `~/.config/kyo/` for templates you want to keep in dotfiles.
